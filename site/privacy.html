Aside Privacy Policy

Last updated: 8 October 2026

Aside is a personal assistant that its developer, Akash Kawalkar, builds and uses for their own personal use. It is not a commercial product and is not offered to the public. This policy explains what data Aside handles, in particular data it receives from your Google account when you sign in with Google.

Who can use Aside

Aside is a single-user application. The only account that is connected to it is the developer's own. No other person's Google data is requested or processed.

Google user data Aside accesses

When the developer signs in with Google, Aside asks for access to:

  • Google Calendar: to read the events on the user's own calendar and to create, change or delete events that make up the user's daily schedule.
  • Google Tasks: to read, create, update and complete tasks on the user's own task lists, so tasks can be ticked off on the phone and shown in the schedule.

Aside does not access Gmail, Drive, Contacts, or any other Google data.

How the data is used

Calendar and Tasks data is used only to display, synchronise and plan the user's own schedule and tasks. It is not used for advertising, profiling for advertising, or any purpose unrelated to this function. Aside's use of information received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements, except as described in the next section.

Where the data goes

  • Supabase (database hosting): schedule entries, tasks, notes and activity records are stored in the developer's own Supabase project.
  • GitHub (GitHub Actions): a scheduled job runs Aside's code. Credentials are held as encrypted GitHub secrets. No personal data is stored in the code repository.
  • Google Gemini API: to generate the next day's schedule, Aside sends the model a text prompt that can contain schedule entry titles and times, task titles, and notes the user wrote. The Gemini API is used on a free tier, under which Google may use submitted content to improve its products. The developer knowingly accepts this for their own data. If you are ever a user other than the developer, this would not be acceptable and the setup would change.

Data is not sold, rented or shared with any other third party, and no person other than the developer reads it.

Storage, retention and security

Data is kept until the developer deletes it. Access to the database is restricted to the developer's own login, and credentials are stored as secrets and never published. Activity data older than a configurable retention period (90 days by default) is removed.

Revoking access and deleting data

  • Revoke Aside's access at any time at myaccount.google.com/permissions.
  • After revoking, stored copies of Google Calendar and Tasks data can be deleted from the Supabase database.

Changes

If this policy changes, the date at the top will be updated.
